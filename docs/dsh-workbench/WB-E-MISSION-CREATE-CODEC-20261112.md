# 正式 Mission 创建请求与选择纯编码

依据 A #288 精确 `b0711004916d3e16d5421ad1f123004cc595c234` 及 B #292、D #293、E #289。V1 request 编码仅接受四个精确预映像字段，使用既有紧凑绑定和九字段映射结构检查。V2 selection 编码包含 goal，三个筛选数组使用 V3 字节顺序并拒重复。筛选项保留已有 V3 ID 语义。原 K 和需要进入 008 text 列的绑定与映射引用采用 384 UTF-8 字节上限。

函数接受普通字典或严格 UTF-8 JSON bytes，返回独立的规范 bytes 和领域分隔 SHA-256 十六进制摘要。读回已有规范 bytes 后，调用方须逐字节核原 bytes 并核原摘要。解码拒绝重复键、浮点、非有限数、BOM 和非法 UTF-8。输入 goal 首尾使用固定码点集合，允许内部控制字符，NUL 与孤立代理项拒绝。请求和选择分别对转义后的规范 bytes 限 65536。编解码不读取任何事实来源。

固定测试向量包括中文、组合字符、非 BMP、内部 U+2028/U+2029、控制字符、引号、反斜杠、BIGINT 最大值、筛选排序与两套摘要前缀。覆盖同键变更 goal、错误 authority/批次、转义后超限、原 bytes 重验与多种损坏输入。本地新增 7 项测试通过。正式事件、回执、PG、Host、HTTP 和 R1 写入未接入。
