# 隔离 PostgreSQL 与 R1 联合恢复验证

承接 D #285 的第三步，复用 B #296 版本化门禁夹具与 D #304 POSIX 物理账本夹具。在真实 PostgreSQL B06 数据库和一次性 R1 文件上运行。进程不访问银行或正式账本。

- 写进程持物理锁后提交 PostgreSQL 标记。并发接管返回 LOCK_BUSY，真实 ACL 撤销返回冲突，标记保持。
- 写入前终止进程。新进程取得同一物理锁，检查空账本。陈旧代次不能清理，原代次可按条件更新。重复恢复不追加事件。
- 写进程执行 fsync 后立即退出，调用方无回执。新进程冷读并核对唯一原行，清理原代次。重复恢复保持同一原行。
- 重复原行和截断尾部均保留标记及原始字节。此夹具只接受空账本或精确原行，避免把投影折叠误作唯一来源。

回放只验证原有临时 Mission 行。生产正式事件、全源关联、写入权限闭包、存储故障、HostFence 和 Windows 资格需要单独验收。POSIX 锁仅约束参与同一协议的进程。
