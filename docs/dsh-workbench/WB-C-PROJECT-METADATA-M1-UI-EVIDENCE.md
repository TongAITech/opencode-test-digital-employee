# M1 项目改名界面候选

初始联调基线为 A PR239 `20a24361cc2292dbbd9c51d820c572844b62fa9b`，包含 B 旧 009 候选。F246 已拒绝其治理并发边界。新的治理修复、`can_rename` 响应及 A 的精确联调源是完整正向验收前置。

概览使用真实同源 metadata GET/PATCH。受治理且服务端明确允许改名时，浏览器还需要当前宿主写入证明和原主体 context。缺少 `can_rename` 的旧响应只可读取。名称校验按 Unicode 标量和 UTF-8 字节计数，首尾只移除 U+0020。请求 revisions 保持规范十进制字符串。界面以文字呈现服务端名称。

请求体、路径目标、request ID 和原主体 context 在首次发送前固定。发送后结果未知时保留内存中的原请求，换主体时拒绝提交该请求。收到回执后再核接收主体，旧回执只确认原操作，当前名称来自随后的 GET。目录专用刷新保留稳定 project、batch、DATE 与已验证 Scope。明确撤权仍清除已加载的授权范围。

- 在增加 `can_rename` 门禁之前，早期原生浏览器试跑使用 20a24361 真实 009 和服务器。实际隐藏重名被拒绝，真实改名提交后由服务器断开 socket，原主体重试取回原回执。该次测试随后在等待当前名称的断言处失败，原因是历史确认先于后续 GET 完成。测试已分别等待当前名称和目录刷新，早期试跑仍记失败。
- 新的完整浏览器测试要求真实服务端提供 `can_rename`，在旧源上没有完整正向通过。测试含真实提交断线、重试原 body/context、不同主体拒绝、旧回执后较新名称、NO_CHANGE、隐藏重名、CAS、reader 只读、不同项目迟到响应、长名 375px、键盘、保留合法 Scope 及无业务 localStorage。

## 新服务端候选联调

在原候选上前向合入 A PR239 `26ef3c7b4173f9dd0a2b5240edd1039fb5a428ae`，其中 B 009 为 `3b74d5e0`。实测环境为独立 PostgreSQL 17.6 ICU、同源 HTTP 和普通 Chromium 原生 fetch，宿主身份来自明确的测试夹具。

- 新改名浏览器用例定向通过。最终全套浏览器 **11/11**，无跳过，53.285 秒。最终 Node **124/124**，无跳过。
- 真实服务端返回 writer `can_rename=true`、reader `false`。缺字段的旧响应降级验证只读。
- 真正提交后由服务端断开 socket。原请求 body 和 context 保持一致，Bob 不发送 Alice 的原请求。另一次已提交成功回执延迟到切换主体后送达，界面保持未知并清当前字段，回到 Alice 后原请求对账成功。
- 首次实际 HTTP 400 `REQUEST_FIELDS_INVALID` 和 403 `WRITE_CONTEXT_REQUIRED` 由请求传输故障注入触发，服务端拒绝并保持历史计数为零。首次明确拒绝后可重新填写。恢复阶段实际 403 保留原请求，之后取回原回执。精确 409 `REVISION_EXHAUSTED` 映射已纳入允许清除首次请求的协议代码集合。
- PG 历史、outbox 与当前名称核对了隐藏同名拒绝、CAS、NO_CHANGE、旧回执之后读取最新值。项目目录刷新保留原批次、已验证 Scope 与需求筛选。真实迟到 GET 在切项目和主体后无法覆盖新项目显示。
- 原生键盘、375px 长名和两语流程通过，业务值未写入浏览器 localStorage。集成仍以 B/A 和 C 的独立精确源接受为条件。

## F252 撤权反例及修复

在旧 `a99b09c5` 上执行 F252 `21571658` 的独立脚本。真实项目 ACL 被删除后 PATCH 和 GET 均返回 403，仍观察到 `REVOKED STATE READY P1 B1`。旧源实际失败，4.72 秒。

业务 PATCH 403 FORBIDDEN 触发同项目 metadata 重新读取。GET403 或读授权无法再次确认时，清除该目标已加载的名称、项目和批次选择、Scope 及目录显示。若 GET200 仍可读，则对已加载的同 project/batch/DATE 重新执行 B06，读取期间隐藏旧 READY 记录。新 Scope 的安全整数 epoch 转字符串与 metadata 的精确十进制 epoch 比较，验证后逐层保留仍合法的需求、版本和 SST 筛选。目录刷新采用新验证的 epoch。被更新 Scope 操作取代的检查，以及其他项目的迟到响应，均不能清除当前范围。

Host/CSRF 拒绝保留已授权读范围。未知恢复的原请求继续以原主体、原 body 和原 context 保存于内存，撤权清除展示数据。恢复权限后，Bob 不能发送 Alice 的请求，Alice 可按原请求对账。

- F252 原脚本在修复后通过，4.96 秒。
- 最终 Node **124/124**。真实 PostgreSQL 17.6 ICU、同源 HTTP 与原生 Chromium 全套浏览器 **11/11**，52.875 秒，零跳过。
