# 正式运行批次九字段描述与请求摘要候选

基线 b05f7f3e。承接 D #263、F #264、B #265、D #267 和 E #272 的边界。本增量实现已解码描述的纯结构比对，供 F 独立验收。模块不接入 E01/E02、008 写入、R1 或 Host。

## 描述和摘要位置

- 描述保持九字段精确集合。版本须为整数 1。七个共同文本字段逐字等于紧凑绑定及其 mapping，不修剪、不做 Unicode 归一化。runtime_release_batch_id 独立保留，后续须与同原 K 的 008 持久预留及 canonical ReleaseBatch 三元组和全部相关历史比对。不得从 PG batch_id 或 runtime_release_id 推导该值。该纯阶段只验证自身格式，三种 ID 所属的命名域及唯一性由来源层证明。
- 将 #263 中“摘要纳入描述及永久操作引用”的位置收敛为 E #272 的无循环做法。现有紧凑 15 键中的 request_digest 是创建事件内的摘要载体。独立九字段描述进入该摘要的预映像，其中已有 creation_operation_ref。描述不再加摘要键，operation ref 保持原 K durable PREPARE 固定的独立标识。008 存相同摘要、原规范字节和操作引用，正式事件和回执按原 K 查验。若事件外层另存摘要，须与紧凑绑定完全相等。
- 完整请求摘要应覆盖 K4、无摘要的紧凑绑定业务内容、完整九字段描述和所有影响首次 Mission 创建的不可变输入。按已签协议固定领域前缀、规范 UTF-8 JSON、字段清单、字节边界和跨语言向量。当前保留未冻结点：正式命令正文（包括 goal 等构建字段）、具体外层事件键、回执原始字节和载体大小。先冻结这些边界，再实现正式摘要生成与验证。用于重试比较的 PG selection_digest 是另一域。
- 该函数只接收解码后的普通 dict 与结构 ScopeIdentity，利用现有绑定序列化重验其结构。重复 JSON 键检测归正式原始事件解码器。返回不可变的九字段值供后续比对。格式通过不声明该描述来自正式创建事件、原始事件唯一、Scope 可见或允许执行。

## 验证

新增四项纯测试，覆盖三个不同的 ID、精确字段及版本、所有共享身份冲突、未绑定 Scope、输出脱离输入及有效的独立 ID 变体。与九项紧凑绑定回归一起运行。工作流在 PR 的实际 HEAD 上使用 Python 3.8 和 3.11 执行两组测试。
