# D 物理账本进程持有验证

承接 #285 第二步。使用临时目录、真实独立进程和现有 R1 Mission 序列化及冷回放。测试夹具以约定设备号和 inode 打开文件，对同一描述符申请 POSIX flock，并在同一描述符写入和 fsync。该夹具不进入生产包或运行入口。

- 持有者存活时，同路径和同 inode 硬链接的竞争进程均收到 LOCK_BUSY，账本保持空。终止持有者并等待进程退出后，恢复进程可通过硬链接取得同一文件锁。它拒绝上一代请求，接受当前代请求后，两个名称下可读到同一份字节，正式冷投影中有且仅有一条测试 Mission。
- 路径被替换后，已有进程下一请求拒绝，尝试打开替换路径的进程也因物理身份变化拒绝。原 inode 的锁仍生效，替换前后两份文件都没有新增字节。
- 原生 R1 通用写入口仍可在该 POSIX advisory lock 持有期间通过另一进程追加。冷回放确认真实记录存在，随后遵循协议的竞争进程仍收到 LOCK_BUSY。生产需要独立的写权限闭包。该探针未证明部署后旧写入器不可达。

代次由测试进程显式传入，用于证明新持有者识别旧请求。持久代次分配、R1 写权限部署、跨存储恢复、文件路径并发运维和跨主机文件系统均须另验。Windows 在此夹具中明确跳过。CI 使用 Ubuntu/macOS 真机矩阵。
