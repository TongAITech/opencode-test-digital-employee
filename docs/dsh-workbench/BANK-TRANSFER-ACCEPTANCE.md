## 什么时候搬运

只在集中回归后的候选验收点准备一次搬运材料。必须标注完整 source SHA、变更清单、已通过的行外检查、尚缺的行内门禁、每个依赖的版本/哈希/许可证，以及采集脚本的相同 SHA。普通小提交不重建 Windows 离线整包。

当前 PostgreSQL/HTTP/浏览器与 R1 组件测试只证明行外源码行为；fixture Host provider 不能作为实际宿主认证。未满足正式发布门禁前，材料须明确标为验收候选，不得称最终银行交付或许可证批准。

## 搬运前必须具备

- 可审核的独立原创来源与第三方依赖清单，不包含未经授权的 PolyForm Noncommercial 受限源码。
- Windows 非管理员、Git Bash、离线 Python/Node/PostgreSQL/浏览器运行时的版本和哈希清单；不依赖行内在线安装。
- 受控配置模板：数据库使用业务运行角色，迁移使用单独 owner；Host provider、签名信任根与会话认证必须由真实 DSH 接口接入。缺接口默认拒绝，不能搬入测试身份provider代替。

## 入行第一轮只读观察

先确认候选源 SHA 与文件哈希，再在实际宿主机器使用候选中既有探针。以下为仓库真实命令；python 必须来自候选中已验的离线运行时：

```bash
python tools/dsh_workbench/wb_d_host_probe.py --url http://127.0.0.1:4096 > host-readonly-probe.json
```

该探针只访问 loopback 的会话状态接口，不创建会话、不发送对话、不读密钥、不写 DSH 或 R1。退出码2表示未观察到合法接口；退出码0/SCHEMA_OBSERVED只证明接口形状被观察，不证明版本、身份、面板或业务通过。实际端口不同时仅替换为现场确认的loopback端口，不猜测远程入口。

随后由 D 核对真实 DSH 1.18.26 的原生面板生命周期、可信认证/撤权接口、稳定用户到项目 ACL 的映射、CSRF/Origin、模型/会话/历史/附件/Skills/Commands API。未验证的接口继续 UNKNOWN，不能回退成浏览器自报 principal。
