## P1 · 保存收到拒绝后仍展示已撤权项目和批次范围

在独立 PG17.6 ICU、真实同源 HTTP 与原生 Chromium 中，以 Alice 打开已治理 P1 的改名表单，同时保留 P1/B1 和 R1 需求筛选。通过隔离 fixture 的行政连接正常撤销 Alice 的项目 ACL，然后从原表单保存。真实 PATCH 返回 403 FORBIDDEN，页面报告权限拒绝，历史行数保持不变。另发 metadata GET 同样返回 403，确认该主体已失去读取资格。此时浏览器仍显示项目 P1 和批次 B1 已选中，`#business-scope[data-scope-status=READY]` 仍成立。独立用例实际失败，1 项，4.74 秒，观测为 `REVOKED STATE READY P1 B1`。

`project-metadata-panel.mjs:253–262` 对 PATCH 的拒绝只清 metadata、subject 和 form。GET 路径已有清除已加载授权范围的入口，PATCH 路径没有重查读权限或触发同等失效处理。PR250 的证据文件明确要求撤权清除已加载的授权范围。修订验收须覆盖写权限单独撤销和完整访问撤销，避免把任意写证明错误误判成无读权。未知请求的原主体回执恢复仍需保持，不能因撤权或改选而更换原请求。

复现以原 `tests/browser/test_project_metadata_product_browser.py` 为夹具，在 `self.assertEqual(patches[-1], delayed_intent)` 后追加以下步骤。单独用临时副本运行，未修改候选文件。

```python
before_history = data.scalar('SELECT count(*) FROM wb.project_metadata_history')
db.owner.execute("DELETE FROM wb.project_acl WHERE project_id='P1' AND principal='alice'")
with page.expect_response(lambda r: r.request.method == 'PATCH') as response:
    rename('rename after project access revoked')
self.assertEqual(response.value.status, 403)
self.assertEqual(response.value.json()['error']['code'], 'FORBIDDEN')
wait_status('permissions or identity')
self.assertEqual(data.scalar('SELECT count(*) FROM wb.project_metadata_history'), before_history)
self.assertEqual(page.request.get(origin + '/api/workbench/v1/projects/P1/metadata').status, 403)
self.assertNotEqual(page.locator('#business-scope').get_attribute('data-scope-status'), 'READY')
return
```
