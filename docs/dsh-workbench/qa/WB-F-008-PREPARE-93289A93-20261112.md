# F 独立复验 008 PostgreSQL PREPARE 隔离夹具

接受 [PR #278](https://github.com/TongAITech/opencode-test-digital-employee/pull/278) 精确 `93289a93787225e48cc251c2a4c5fdbf26045f6c` 的 ISO DateStyle 隔离夹具。真实 PostgreSQL 17.6 + ICU 上原 10 项通过、零跳过，7.303 秒。覆盖两位实际等待者同 K 单次提交、冷重放、不同选择冲突、缺日志整事务回滚、独立运行批次唯一性、跨 K 回执外键、角色权限、非空回退及 008/009 两种夹具 DDL 次序。

独立探针另用真实 PostgreSQL 两连接及 `pg_locks` 确认竞争请求已完成首次 ACL 检查并进入同 K 等待。等待期间提交完整撤权，释放锁后新写入被 RLS 拒绝，SQLSTATE 42501，四表均零行。恢复权限后，在另一次真实等待中取消语句，得到 57014，连接回到 IDLE，四表仍零行。正常冷连接重试提交一份 snapshot、intent、PREPARE，原 K 用更新的快照 revision 和不同测试预留重试返回原运行批次，数据库仍保存原 revision。实际只读成员在三个开放 SELECT 的表均看不到记录。非空 down 再次返回 55000，四表行数保持 (1,1,1,0)。

P2 夹具可移植性仍有红灯。将请求会话的 DateStyle 切到 German, DMY 后，`release_date::text` 与快照 ISO 日期不等，合法首次请求返回 `SCOPE_008_SNAPSHOT_CONFLICT`，所有行均回滚。正式端口复用前须改成按日期类型比较或证明固定格式。

夹具连接使用受控 `wb.principal`，测试结果只证明该主体上下文下的数据库行为。生产主体绑定、权威身份分配、正式请求摘要、回执、迁移组合 runner、Host 和跨存储撤权顺序仍待实现及验证。正式 R1 append 保持 HOLD。
