# B 组版本化围栏隔离实库证明

承接 A #275 和 D #285。测试在真实 PostgreSQL 17.6 的独立数据库安装 001–005，沿用真实 B06 fixtures。仅测试内创建一张每项目单行的围栏表。登记、撤权参与和清理使用条件 UPDATE 原子判断并推进 generation。日期与关联变更由隔离测试触发器在真实业务事务内接入。

- 同一已登记行存在两个实际 SQL 等待者。REPEATABLE READ 事务先读取无标记快照，登记提交后得到 40001。READ COMMITTED 等待者重新核条件后返回冲突，两次均未撤权。旧 generation 清理被拒，当前 generation 清理后真实 ACL DELETE 提交，B06 返回 403。
- 登记提交后实际终止其数据库连接。新连接仍看到原标记。真实日期变更及关联加入均被拒，日期、修订、关联行、日期历史和审计计数不变。另一个项目的撤权可以提交。测试清理后，原日期和关联动作在新事务中成功。
- 撤权先提交时，登记事务进入同一围栏顺序后可见已撤权状态，B06 拒绝读取。这一用例仅验证可见性。
- 三个 PostgreSQL 用例实际通过，零跳过。测试清理以预期 generation 比较作为 fixture oracle。生产清理必须另有 R1 写入权与原事件核验，当前没有生产代码依赖此表、函数或角色权限。

这一测试覆盖代表性的单项目 ACL、日期和关联路径。正式设计需要统一顺序以避免测试触发器的业务行后取围栏锁与正式登记的取锁顺序冲突，也需要覆盖跨项目 ACL 移动、目录权限、维护操作、真实 Host 撤权及旧 R1 写入者隔离。测试没有调用 R1。
