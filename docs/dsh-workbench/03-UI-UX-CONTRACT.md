# UI/UX 设计契约
状态：W0_DESIGN_IN_PROGRESS / W0_NOT_FROZEN；W0 候选合同待 A01/A03/F00 正式签署；W1–W4 实现与现场 QA 未运行；A02 BLOCKED_LICENSE

## 布局
DSH 原生侧栏中一个“测试工作台”入口。六大主页面不改名不删除。项目详情由项目/看板入口打开，左侧保留十个原分区；顶部显示当前项目与投产日期（yyyy-MM-dd）及需求/系统版本/SST 联动筛选；中央内容按分区切换；右侧可展开 DSH 原生 AI 助手，默认不占用过多宽度。
页面简洁、克制、中文一致，避免十几个巨大卡片和密集无效装饰。允许专有缩写 SST、DSH、CodeGraph、Libra、CAT。界面切换英语时必须为完整语言模式，不允许仅局部翻译。

## 功能与导航原则
原有 DSH 对话是完整一级页面；项目内助手复用宿主 DSH 会话能力，禁止第二套模型密钥/会话存储。原六阶段看板可以操作项目业务状态，但“已发布”必须查询正式 N10 和人工审批，不可拖动强制通过。
需求分区子视图：需求结构/业务规则/代码影响；用例分区：测试义务/设计/评审/数据；质量任务：Mission/编排/准备/执行/诊断/证据；缺陷/报告/知识/门禁保留原有入口并增强。

## 状态展示
所有指标展示“数据截至/来源/批次范围”；未知=未知、未执行=未执行、被阻断=被阻断；不能以模型生成结果冒充执行通过。能够从项目→日期→需求→版本→SST→义务→用例→Attempt→证据双向跳转。
显示错误原因和恢复入口；没有有效 SST 的版本关系显示“待拆分”，而不是隐藏。

## 必验体验
六大页面、十个分区不回退；主题/搜索/侧栏折叠/附件/历史/模型/技能/命令正常；移动窄屏至少可完成查看和过滤；所有日期时区以银行业务时区约定，不能使用浏览器 UTC 转换造成日期偏移；项目切换不串上下文。
