## Exact boundary analysis before any source repair

1. r2_2/orchestrator.py:140 defaults to RuntimeFactsResolver(). _create commits CREATE_MISSION before _resolve and CREATE_GOAL. Existing mutation/transaction order is frozen.
2. r2_1/resolver.py:287-346 provides only ObservationSnapshotStore backed by storage.all_rows/one and truth.add_snapshot on truth_snapshots. Its public behavior includes global resolution_id lookup (not project-partitioned), request_digest conflict rejection, stable snapshot identity, complete resolution payload and read(snapshot_id). resolve() performs that lookup before normalization work and saves its result before returning to intake.
3. canonical_runtime.py registers 27 extensions; R2.1 is described as an orchestration/query service, not a durable extension. The enumerated registered command/event contracts contain no dedicated R2.1 observation snapshot command. durable_core has no general observation/snapshot store API.
4. The real R1 evidence interface is tool_execution/service.py:230 record_evidence. It rejects evidence with no prior ToolExecution. ToolExecution requires an OPEN runtime Session/current Plan, ACTIVE Task, matching Attempt, fixed context cursor and ProviderBinding (service.py:309-342). None exist at the failing intake boundary, before Goal/Planner. Inventing them just to store a resolver snapshot would change governance/order and is not an adapter-only repair.
5. G2.1 record_observation is specifically Session observation, not a general runtime-facts snapshot. G3_RECORD_FACT has a frozen FACT_KINDS allow-list without R2.1 resolution. Using an unrelated kind would misstate domain truth.
6. R3.E1 can physically carry structured KnowledgeFact/KnowledgeVersion payloads, including a RUNTIME source category. However, repurposing its scope-owned Knowledge lifecycle as global pre-Goal R2.1 snapshot authority is not an established contract mapping in this baseline. This executor does not assert that reuse is impossible; it cannot claim that such a new interpretation preserves frozen knowledge/retrieval/identity semantics without 00.10 deciding the mapping.
7. Storing only in an in-memory cache loses restart/global conflict detection. Using a sidecar DB/JSON violates sole Truth. Embedding a new snapshot protocol in Goal/Mission attributes or saving after Goal changes durability ordering/contract rather than merely binding an existing interface. New standalone R1 event/schema is explicitly outside this authorization.

No candidate above has a demonstrated existing, semantics-preserving adapter mapping. Therefore no production source patch has been made. This is a concrete contract boundary, not a request to separately reauthorize the already-authorized default-resolver bug fix.
