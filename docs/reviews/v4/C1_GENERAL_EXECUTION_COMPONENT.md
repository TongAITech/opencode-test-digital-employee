# V4 C1 General execution component — candidate, not qualified

The product now delegates an admitted actual Host clause to a typed GeneralWork or RuntimeDiagnosis root, creates a separate OpenCode worker Session, and performs bounded workspace file reads, searches and optimistic writes. The Primary has no direct filesystem/process authority. Runtime matches every worker call against the actual running Host tool part, current Session, agent and exact input. General jobs create no Mission and cannot write formal Case/Defect truth.

Same-R1 execution records own job-local task/attempt/agent identity, Session epochs, fixed policy leases, prompt claims and call receipts. Each file write has a preimage/hash/diff and an R1 claim before effect. Unknown writes are reconciled by readback, never blindly repeated. A readback-equivalent state is not proof of physical write count. Completion requires observed same-job work and, for writes, references to produced files with fresh matching hashes; it does not prove every semantic obligation is correct.

Recovery resumes accepted General intent from canonical Interaction receipts even if the process died before job creation and original conversation is unavailable. It resumes CREATED jobs, reconciles lost read observations and revalidates checkpoint/completion references before recording their result. Expiration is anchored to the original Host observation; restart does not renew authorization. Old receipts without operation_text retain their original shape. General intent is committed in a distinct interaction.general_intent_recorded.v1 event atomically with the original claim. The existing event-type compatibility guard rejects a typed-root composition without this event owner; the 1.1.0 manifest version alone is not a compatibility guard. This does not qualify unmodified historical binaries that predate the guard.

The POSIX broker uses held directory handles and atomic displacement for existing files. A concurrent edited/displaced version is preserved on inspection failure; an unchanged worker postimage permits restoration. New files use exclusive installation. Reparse/symlink/hardlink/ADS/traversal/protected runtime/auth/state paths are denied. Windows implementation is present but its replacement and process isolation paths are **NOT_QUALIFIED**. Terminal and git_inspect remain explicit GENERAL_OS_CONFINEMENT_UNAVAILABLE, with no unrestricted subprocess fallback.

## Oracle correction

The pre-General implementation's assertion that admitted engineering work creates zero R1 events was invalid once typed non-Mission jobs were implemented. The revised oracle still requires zero events for chat/negation/reference, while admitted General/Diagnosis must create their own durable roots and real Sessions with **zero Mission**. This is a scope-correct oracle migration, not relaxation of Mission admission. Outer Host tool status `completed` is never treated as successful terminal execution when its structured result reports FAILED.
