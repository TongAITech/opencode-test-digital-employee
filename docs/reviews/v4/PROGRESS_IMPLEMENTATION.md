# V4 progress and prompt delivery implementation

The existing Supervisor now invokes the existing Scheduler after health observation and performs a bounded same-session wake for nonterminal idle work. Busy, retry, human Gate, inactive Mission and unknown delivery states fence fresh work. Runtime coordination is a process file lock only; it stores no workflow truth. Decisions, session provisioning and prompt delivery receipts remain in R1. Task failure produces explicit technical failure, never a SUT quality verdict; completed worker tasks still require the separate quality assessment.

Each initial/wake prompt has a unique Runtime dispatch identity in the actual bytes sent, an R1 CLAIMED receipt before sending, and ACCEPTED/UNKNOWN afterward. A real process death leaves CLAIMED and forbids blind resend. Bounded directory-scoped Host message readback may reconcile a matching user message and record its immutable ID/hash. An absent/unavailable/ambiguous message is not proof that sending failed. This prompt journal is not a business exactly-once guarantee; the G4 business-side-effect ledger remains separate work.

The Runtime serializes concurrent scheduling/completion and intake transitions. Successors reuse their own provision and root Attempt binding when legacy R2.5 core attributes omit the role. At most three rotations without accepted business progress trigger diagnosis-required WAIT, including alternate router recovery paths. Heartbeats and prompt/rotation receipts do not reset that count. Diagnosis execution and full process/in-flight resource coordination remain to be connected.

Two nine-scenario runs at 0.15s and 1.1s controller intervals passed: sequential workers, idle wake, one recovery, busy and busy+pressure, explicit worker failure, receipt-before-crash dispatch recovery, independent work during Gate, and bounded repeated failures. The original contradictory idle process-count assumption was independently corrected as documented. Four journal tests use concurrent OS processes and real process exit before/after fixture transport; 15 pressure tests and 30 router checks pass. These are incremental component results; the final source-sealed Windows/default-entry/real-model package qualification is still outstanding.
