# C1 HumanGate owner and continuation increment

1.14.0 CANDIDATE / NOT_QUALIFIED. Full C1, C2–G and final installed-byte qualification remain open.

Actual Host clauses enter the existing Primary interaction path. Completion words authorize only a request for fresh verification. The owner searches all authorized, scoped Missions for a unique compatible pending Gate; it does not first require one unique Mission. Quoted/conditional/negated content cannot authorize handback. A model Gate hint cannot pick a Gate. An atomic interaction claim fixes the original Mission, Gate, takeover, root Attempt and browser digest before effects. Replay uses that claim even if current candidates change.

A typed HUMAN_GATE_RESUME root in the same R1 store coordinates explicit and AUTO requests for that Gate. It creates no Mission, Task or Session. Verification, handback intent, exact R2.6 decision, completion facts and continuation receipt are separate recoverable phases. A committed R2.6 decision is inspected before recovery; a lost return never triggers compensation or a different decision. Stable G4 lease records allow a new CDP adapter to recover ownership without its old process memory. Frozen R2.6 and G4 schemas/handler identities are unchanged.

An unstarted request retains its original Host expiry. After expiry it cannot advance; a new actual Host request may record REAUTHORIZE while no handback effect exists, preserving the original Gate/context/lineage. Already-started handback recovery does not depend on re-reading Host history. Background recovery includes requests and resolved Gates whose owner receipt is unfinished.

A UI continuation is durably SENT with an exact request digest before physical execution. An absent receipt remains UNKNOWN_SIDE_EFFECT. Both repeated resume and ordinary G4 execution are fenced. Only the current owner receives an ephemeral, single-use permit for the journaled request; model payloads cannot provide it. This is the local continuation safety increment needed for HumanGate integration, not closure of all API/DB/UI side-effect reconciliation under C3/D.

Local verification uses real R1/G4 with explicit Host/browser transport fixtures. Tests cover per-phase crashes, committed decision with a lost return, changed context, concurrent controllers, AUTO versus explicit requests, multi-Mission unique/ambiguous/unauthorized selection, expiry and new-request authorization, continuation loss and public G4 bypass rejection. A fresh production CDP adapter with substituted observation transport verifies durable lease recovery; it is not labeled actual Chromium execution. Frozen typed-root/golden20, interaction37, Primary11 and control16 regressions passed before the final test expansion.

Independent review found and reproduced a missing public-G4 SENT fence and an expiry boundary gap; both were repaired and independently rechecked. See HUMAN_GATE_RESUME_RAW_REVIEW.md. Local actual Chrome launches failed at the macOS process boundary (_RegisterApplication SIGABRT / Chromium crashpad bootstrap permission denied). Failed logs are retained. The Windows workflow reuses the existing pinned offline Chromium/Python payload and runs the actual-browser recovery script against a disposable local DOM. Its result must be inspected before claiming real Windows browser PASS.

Multi-Mission fixtures share one Host and use distinct domain IDs, matching the current frozen G4/R2.6 global command identity contract. A proposed service-only idempotency-key change failed the existing G4 handler and was withdrawn, with its failed source/log preserved. Same-named Goal IDs across Missions remain an existing implementation limitation; this increment does not claim to fix it or require users to manage internal IDs.
