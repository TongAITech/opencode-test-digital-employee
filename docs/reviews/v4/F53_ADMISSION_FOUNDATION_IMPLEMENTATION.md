## Implemented boundaries

- The official Director entry exposes `status`, `interact`, `start_test`, `continue_test`. Mutations obtain the actual host session/message from the official ToolContext bridge and fetch the corresponding host response. Assistant-parent, response identity, same-session parts, synthetic/ignored content, age (15 minutes), future skew (30 seconds), exact text and UTF-8 content digest are checked. Model-supplied provenance and raw request fallbacks are rejected. Host age is rechecked before execution. Direct local Python APIs remain trusted internal APIs; SYSTEM actor strings alone are not a security boundary.
- A real host model can propose nine typed intents and one operation for each complete runtime-provided clause. Strict proposal schemas reject authority flags and incomplete clause slicing. Deterministic admission assigns each action its effect and rejects negative, quoted, explanatory, conditional, example and question forms before testing effects. This is a conservative admission grammar, not a general semantic classifier. Unsupported natural-language forms ask one clarification.
- Exact literal scope preserves version spelling, removes only terminal Chinese `版本`, forbids empty scope and version-prefix matching, and isolates mixed-operation scope. Canonical R1 reads resolve zero/one/many existing Missions; unrelated-session references cannot be invented by a model. Chat/query and GeneralWork/diagnosis routing do not create Missions or grant I/O.
- `INTERACTION_OPERATION` is a receipt-only registered root in the same R1 transaction/event store. It creates no Mission, Task, scheduler item or execution Session. The immutable host/operation/request/target/scope claim uses CAS and transactional idempotency. Same clause reclassification keeps the same operation identity and conflicts. Retry compares all nine immutable fields. Canonical resolution is retained for replay even when candidates subsequently change.
- Receipt transitions are `CLAIMED -> BOUND -> COMPLETED`, or `CLAIMED/BOUND -> RECONCILE_REQUIRED`. A claim grants no effect authority. Mission bind checks the actual root and scope; GeneralWork/RuntimeDiagnosis bind checks actual root, operation identity, full host provenance and explicit purpose. The receipt projection is rebuildable and is never the source of truth.
- Fresh admitted starts and continues use the existing R2 intake and actual G2/G2.1 orchestration services. Completed operations replay their stored bounded result; unresolved receipts never redispatch. Faults after possible session dispatch remain reconciliation-required. Completion results contain allowlisted status and subject/session/task identifiers, avoiding G2.1 internal provisioning tokens/capsules.
