# Native Mission factory and run entry

`create_mission_driver` owns the implemented N1/N2/N3/N4/N5/N6/N7/N8/N9/N10
service composition. N6 and N8 remain the existing driver/pipeline routes.
The factory accepts capabilities, not node callbacks or a replacement driver.
Construction launches no Worker, performs no business operation, writes no R1
event and grants no Field admission.

The eleven exact professional roles are reality, requirement,
requirement_review, source, source_review, code, code_review, design,
design_review, data and data_verify. Each has a typed launcher, a distinct
private state directory and an exact non-wildcard tool set. Shared/nested role
directories, shared launcher instances, other ledgers/releases, an unattested
mirror dictionary or an untyped execution adapter are refused before composing
pipelines. Native N1 uses the parent-owned input-read launcher. The code
producer and reviewer both retain Git and CodeGraph.

The factory constructs and owns the expected original scope provider, formal
N7 execution/preparation/cleanup/review, accepted-scope N9, measured coverage,
coverage gap intake/diagnosis and native N10. All share the exact source and R1
scope. Existing mandatory Q7/native bank pip mirror admission and every stage's
evidence gates still apply. A host binding cannot supply a PASS through this
interface. The existing native N10 terminal review is still OPEN: completing
composition does not implement terminal review or BANK_FINAL.

`python -m rc7_release.rc72_mission_cli status` keeps the existing read-only
interface and requires no model/Worker/host binding configuration.

`run` additionally requires `--release-id`, `--package-root`,
`--bindings-module` and `--evidence-root`, alongside `--ledger`,
`--release-batch` and `--source-commit`. It checks the package SOURCE_COMMIT and
canonical batch release before importing the host module. The approved local
module exports `create_mission_bindings(truth=..., release_id=...,
source_commit=...)` and returns exactly `MissionHostBindings`. The module is a
trusted installed integration, like the inherited execution environment module;
its arbitrary Python code is not a security boundary. Its return contract is
capabilities only. Host exceptions are reduced to exception type so private
configuration values are not printed by the loader. The native mirror provider
must bind the same running package root. Existing per-batch controller locking
and cold evidence audit remain in the native driver. Known contract failures expose only a safe reason code and current run results
return exit 37; no implemented terminal closure currently authorizes a success exit.

`packaging/rc7.2/MISSION.cmd` uses only the package Python, clears Python import
injection, reads the package source automatically and fixes package/source flags
after caller arguments. It preserves the bank Windows profile. The package
identity requires this command, CLI, typed binding loader and native factory.

This is partial C08 implementation. Default package/host bindings, private DSH
SDK/provider provisioning, all-role physical call-time fences, professional
semantic repair and native terminal/final closure remain required construction.
Real bank Field is performed by the user after transfer; engineering protocol
children, synthetic prior approvals or local HTTP tools are not bank facts.
