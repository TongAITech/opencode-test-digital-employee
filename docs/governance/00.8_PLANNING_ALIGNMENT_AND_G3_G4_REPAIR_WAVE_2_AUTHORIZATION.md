### 1.5 Correct Code / Change Intelligence provider model

The formal G3 provider model is:

```text
Git Provider (MANDATORY BASE TRUTH)
+ Reference/Search Provider (ripgrep where available)
+ CodeGraph Provider (where available)
+ Language Provider(s)
+ API / Schema / Config Provider(s)
-> Canonical Change Intelligence
```

The correct responsibility split is:

```text
Git:
  exact repository/base/head
  changed files
  changed lines
  immutable Change Truth

CodeGraph / GitNexus-class provider:
  symbol graph
  enclosing symbol
  caller/callee
  reference/dependency
  cross-file/module structural impact
  only when a real verified provider is available

Language providers:
  syntax/enclosing-symbol fallback or corroboration
  Python AST; Java/JS/TS/Vue structural providers as available

ripgrep:
  best-effort reference enrichment
  never a structural-truth substitute

API/Schema/Config providers:
  non-code and system-surface impact

Every provider:
  AVAILABLE / PARTIAL / UNAVAILABLE / BLOCKED
```

**Important correction:** CodeGraph/GitNexus is not required to pretend to be AVAILABLE in a Construction package. The formal design says `where available`. If no real adapter/runtime is bound, `CODEGRAPH=UNAVAILABLE` is correct.

But the Runtime **must have a real provider-composition seam** so an available CodeGraph/GitNexus provider can be bound without rewriting G3, and missing CodeGraph must never allow changed lines/symbol obligations to disappear silently.

GitNexus is treated as a concrete candidate implementation of the CodeGraph provider slot, not as a second Change Truth authority.

# 3. Authorized Repair Wave 2

This is an Engineering Repair. No Architecture redesign is authorized.

## R2-1 — G3 Provider Composition & Mapping Completeness

Implement a provider-neutral composition seam, e.g.:

```text
ChangeIntelligenceBroker
  -> GitChangeTruthProvider (mandatory)
  -> optional ReferenceProvider
  -> optional CodeGraphProvider
  -> LanguageStructuralProvider(s)
  -> API/Schema/Config Provider(s)
  -> canonical merger
```

Requirements:

1. Git exact diff remains mandatory authority for changed files/lines.
2. CodeGraph provider interface must be injectable/resolvable.
3. If no verified CodeGraph/GitNexus runtime/adapter exists, report `UNAVAILABLE`; do not fake it.
4. Current package GitNexus slot/README must not claim activatability that does not exist. Either provide a real adapter/enabler or mark it explicitly `PROVIDER_SLOT_ONLY`.
5. Language fallback must track mapping completeness **per changed executable line/hunk**, not merely “at least one symbol mapped”.
6. Any unmapped relevant changed line:
   - provider/repository becomes `PARTIAL`;
   - exact changed-line refs are emitted as `MISSING_SYMBOL_MAPPING` risk/coverage obligations.
7. Prefer structural parser/AST provider over regex.
8. Regex fallback can only be `PARTIAL` unless completeness is independently proven.
9. CodeGraph enrichment may add caller/callee/reference/dependency evidence but may never replace or alter Git Change Truth.
10. Provider provenance/digest/state must be durable and explicit.

Mandatory adversarial tests:
- Java file with one declaration-line change + one unrelated method-body change;
- TypeScript equivalent;
- Vue equivalent;
- CodeGraph unavailable + language provider partial -> no changed line disappears;
- injected deterministic CodeGraph provider -> structural edges/symbol mapping used and provenance retained;
- CodeGraph provider failure -> explicit PARTIAL/UNAVAILABLE, Git diff still complete.

## R2-2 — Governed G4 Execution Binding

All execution truth must be linked to governed G3 work.

Create one canonical validator/binding used by:
- `record_cursor`
- `execute_capability`
- `record_step_result`
- any Manual execution receipt

Require:
- exact G3 `CASE_SPECIFICATION`;
- exact `case_version_id`;
- `CASE_VALUE_LINK`;
- strategy identity;
- durable G4 `ExecutionBatch` membership **or** an explicit governed FocusedExecutionBinding.

Reject fake/caller-only cases.

Prefer:
- public OpenCode surface invokes governed capability execution;
- raw `record_step_result` becomes internal result sink, or requires a canonical manual/executor receipt.

Mandatory negative test:
real Mission/Task/Attempt + `FAKE-CASE` + no G3 Case/Batch => fail closed and no R1 execution-result fact.

## R2-3 — TestingGoal ↔ Bank Coverage Exact Identity

A Coverage Measurement may contribute to a TestingGoal only when identities match.

Bind:
- goal/revision;
- affected application;
- governed target version for that application;
- baseline identity / `MASTER_ALIAS_ONLY`;
- source/provider profile;
- snapshot identity.

If applications deploy different versions, introduce explicit durable:

```text
affected_application_target_versions
```

Do not guess `release_id == every application target version`.

Mandatory negative test:
Goal version/binding V2 + bank snapshot target_version V1 => rejected / source identity mismatch, never `SATISFIED`.

## R2-4 — True Background Browser HumanGate AUTO Resume

Keep current Runtime ResumeConditionVerifier.

Add a non-LLM background supervisor/tick that:
- discovers durable open HumanGates with AUTO/AUTO_OR_EXPLICIT;
- checks same BrowserContext/BrowserLease;
- verifies ResumeCondition from observed browser/SUT state;
- completes/reconciles canonical R2.6 gate;
- returns lease HUMAN -> AI;
- wakes original governed work;
- does not depend on original Conversation/OpenCode Session.

Explicit completion remains supported.

Mandatory E2E:
human/browser state changes from unauthenticated -> authenticated;
**no call to `complete_human_takeover()` from user/test harness**;
background tick detects/verifies/resumes original Attempt/Step.

## R2-5 — TestingGoal Legal Transition Guard

Implement explicit legal durable transition policy.

Terminal states:

```text
SATISFIED
COMPLETED_WITH_ACCEPTED_GAP
BLOCKED
CANCELLED
STOPPED
```

must not transition back to normal active states.

New release/source/goal work must create or supersede a new goal/revision.

Mandatory negative:
SATISFIED + later measurement => same goal remains terminal; no silent `MEASURING`.

## R2-6 — Sensitive Evidence Taint / Redaction

Do not rely on regex guessing alone.

At Browser/API/Auth/Manual evidence ingress:
- classify known sensitive channels;
- redact/drop password, OTP, captcha, cookie, Authorization, token, session/auth values before durable write;
- suspend/redact browser evidence during sensitive-entry mode;
- use typed safe references where possible.

Keep regex sanitizer as defense-in-depth.

Mandatory adversarial channels:
- headers.Authorization;
- Cookie / Set-Cookie;
- access_token / refresh_token;
- session_id / JSESSIONID;
- password/OTP value inside generic `actual`;
- nested evidence metadata.

No raw credential-bearing value may appear in R1 facts/evidence metadata.

## R2-7 — Deliverable Identity Canonicalization

Repair final package identity:

1. define one exact Source Content Identity formula and make it reproducible;
2. emit one current canonical root `PACKAGE_MANIFEST.json` / package identity;
3. move G3 and pre-repair G4 manifests to a clearly historical evidence directory;
4. canonical manifest must represent the final repaired tree and current regression/gate truth;
5. package self-check must fail if multiple canonical root identities exist.
